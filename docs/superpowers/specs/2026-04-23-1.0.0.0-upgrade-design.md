## A — claude-code 升级 **（本 session 不做）**

### A.1 Evidence-based blocker

2.1.116+ 上游改变 packaging：主 npm tarball 不再直接 ship `cli.js`，而是 ship `cli-wrapper.cjs` + per-platform 原生 `@anthropic-ai/claude-code-{darwin-arm64,linux-x64,win32-x64}` 里的 **Mach-O / ELF / PE 二进制**（bun-compile 把 JS 内嵌进可执行 section）。silly-code 的全部 131 patch 都假设 raw JS 字符串匹配，不能直接工作。

### A.2 Phase-0 两条可选路径

1. **B1 — extraction 改造**：扩展 `pipeline/bun-extract.cjs` 或新建 `macho-extract.cjs`，从 per-platform native tarball 抽出内嵌 JS blob，patch 后重新打包回二进制。风险：bun-compile 格式可能非 deterministic，会破坏 patch 的 byte-identical 属性。
2. **B2 — 长期 freeze**：稳定 park 在 2.1.114，按需 cherry-pick 重要 upstream 修复到我们自己的 patch 里。风险：MEMORY 里每轮 `project-upstream-version-tracking.md` 会持续 drift。

**决策**: 本 session 不做 A。落一份 MEMORY critical entry (`project-claude-code-macho-blocker.md`) 锁住结论，归档到本 spec 的 A 段。后续 session 用本 spec 作起点 spike B1 或 B2。

### A.3 如果后续解锁，推荐 step-wise 路径

- Phase 1: 2.1.114 → 2.1.116（perf/UX，最小语义 delta）
- Phase 2: 2.1.116 → 2.1.117（`CLAUDE_CODE_FORK_SUBAGENT`, `/context` 1M 窗口, subagent malware flag fix）
- Phase 3: 2.1.117 → 2.1.118（`mcp_tool` hook shape, agent-hook event gating, `/fork` 指针语义）

绝不一跳 4 版本（evidence 来自 MEMORY `project-dual-stack-drift-surfaces.md` + R1 报告）。
